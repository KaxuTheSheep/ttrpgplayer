Disciplines represent specialised training paths a character develops over time — combat styles, magical traditions, stealth tradecraft, or any other focused skill set defined by the relevant module. Each Discipline is organised as a **tree** of Nodes, purchased individually with Trait Points.

## Structure
A Discipline Tree is a collection of Nodes. Each Node defines:
- **Prerequisites** — what must already be true before the Node can be purchased.
- **Cost** — the Trait Point price of the Node.
- **Effect** — the mechanical benefit gained.

Nodes are typically small, individually modest bonuses (a flat +1 to a Test, a reduced penalty, a new minor option) that compound as a character invests further into the tree. A tree is not one big power gated behind a level requirement — it is many small purchases whose interactions define the character's specialisation.

## Node Costs
Node cost is set individually per Node by the module — there is no universal formula. Early or foundational Nodes in a tree tend to cost less (2 Trait Points is a common baseline); Nodes that combine multiple prerequisites or grant a stronger effect cost more (3–5 Trait Points is common for mid-to-late Nodes).

**Repeatable Nodes** are the exception: a single Node purchased multiple times, with cost increasing on each subsequent purchase, up to a defined maximum number of purchases. A repeatable Node must be bought in order — a module should not allow skipping ahead to a later purchase's cost without buying every earlier step first.

## Prerequisites
A Node's prerequisites can take several forms, and a module may combine them:
- **None** — available to anyone with tree access and enough Trait Points.
- **A single earlier Node** — the most common form, creating a linear chain within the tree.
- **A Node plus a minimum Attribute score** — gating a Node behind both investment and raw capability.
- **Mutual exclusivity** — a module may define two Nodes as mutually exclusive alternatives further down the same tree, where taking one closes off the other, representing a genuine fork in specialisation. This forces players to pick between options rather than dumping trait points into 1 tree and gaining everything mindlessly.

## What a Node Grants
Node effects generally fall into a few recurring shapes:
- A flat numeric bonus to a specific Test or roll.
- Removing or reducing a penalty that would otherwise apply (e.g. Disadvantage on a repeated action, an increased difficulty on subsequent attempts).
- Unlocking a new option that wasn't previously available (e.g. using a stance as a Reaction, or reading extra information from an existing ability).
- Upgrading an earlier Node in the same tree, either replacing its bonus outright or extending the condition under which it applies.
- Trading one resource or restriction for another (e.g. accepting a penalty to one roll in exchange for a bonus to another).

## Access
- Discipline Trees are locked at character creation (level 0) regardless of prerequisites met. They unlock at level 1 (see [[Levelling]]).
- The relevant module defines which Discipline Trees exist and how a character gains initial access to each — unrestricted choice, class/role gating, faction or Faith requirements, and so on.

## Purchasing Nodes
- Trait Points spent on Discipline Nodes come from the same shared pool as Attributes, Skills, and Sturdiness (see [[Levelling]]).
- A Node cannot be purchased until its prerequisites are met.
- Points spent on a Node are permanent; there is no respec baseline in Core. A module may define respec rules if desired.

## Module Responsibility
The Core provides only the Node/Tree/prerequisite framework above. The relevant module must define:
- The full list of Discipline Trees available in the setting.
- Every Node within each tree: name, prerequisites, cost, and effect.
- Any tree-specific gating (e.g. a Divinity tree requiring Faith investment, a Magic tree requiring an in-fiction resource like Mana, an Esper tree requiring the player to be an Esper etc).
